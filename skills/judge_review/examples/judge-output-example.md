# judge_review · 评审输出示例（L3 examples）

## 局部评审（每节一次）

```json
{
  "内容深度": 6,
  "逻辑严谨性": 7,
  "证据忠实度": 4,
  "coverage_ok": true,
  "issues": [
    {
      "type": "no_anchor",
      "claim": "核心事实论断（LTSF-Linear 的设计动机、九基准性能对比结论）完全缺失引用锚点。",
      "problem": "具有争议性的关键结论必须有确切文献支撑，否则构成证据链断裂。",
      "fix": "立即补充原始出处文献（如 Deng et al., AAAI 2023），并以「代表工作[XX]指出……」句式嵌入引注。"
    },
    {
      "type": "faithfulness",

  ]
}
```

## 全局评审（一次）

```json
{
  "结构完整性": 6,
  "学术规范性": 5,
  "即时约束遵守度": 10,
  "记忆偏好遵守度": 10,
  "篇幅遵守度": 10,
  "issues": [
    {
      "type": "style",
      "claim": "引言末尾仅泛泛说明写作目的。",
      "problem": "未交代本文的结构安排、筛选标准与章节演进路线。",
      "fix": "增补「本文剩余部分组织结构如下：第二节回顾……第五节总结展望」的标准路径图语句。"
    }
  ]
}
```

## 规则要点

- 只输出 JSON，不要其他文字；解析时取首个 `{` 到末个 `}`。
- 即使没问题也给出 0-2 条改进项；有问题必须列出。
- 确定性证据两档：确定性问题（no_anchor/no_citation/NLI 矛盾）必须扣分；weak_match 由法官判断。
