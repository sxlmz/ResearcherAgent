# write_review · 写作阶段完整规范（L3 参考，write 节点执行依据）

SKILL.md 正文的精读版本。写作节点（write）执行时若有歧义，以本文件为准。

## 综述结构（优先级：用户指定 > 记忆档案偏好 > 此默认结构）

- 用户明确指定章节 → 严格按用户结构组织，不使用默认结构。
- 记忆档案（USER.md）记录过格式偏好 → 优先用记忆格式。
- 否则用**演进式默认结构**（5-6 节）：
  1. **引言**（1 节）：问题定义（形式化：任务定义/关键假设/复杂度目标——示例：时序为预测长度 Horizon、通道假设；其他领域按领域惯例变通）、研究背景、综述范围与排除标准、全文路线图
  2. **技术迭代**（3-4 节，建议 3）：按**技术世代由远及近、由浅入深**组织——
     经典/统计时代 → 深度学习初期（RNN/LSTM）→ Transformer 时代 → 后 Transformer 改进/轻量化（近两年）。
     **世代划分由 LLM 依领域自适应**（few-shot 引导，具体领域需变通，不写死）。
  3. **展望总结**（1 节）：当前不足、未来方向、结论

## 写作方式（2026-10 方案 v1.2：五步流水线拼接，替代逐节 LLM 自由写作）

write 节点按以下顺序执行（代码确定性流程，模型无需干预）：

1. **内容块生成**（自动，v1.2.13 流式 + 句级锚点 + 结构化键）：每篇字段化卡片 → 2-4 个 JSON 块
   `{block_type: method|intro|conclusion, content, paper_ref(论文标题), paper_num(池内编号=「引用」键),
   evidence(§锚点)}`——**大纲归属（outline_section）由代码按 block_type + 卡片所属大纲节确定性标注**；
   **产出规则硬约束**：方法内容必出 method 块（四要素句式）、背景必出 intro 块、
   结论必出 conclusion 块、纯摘要卡出 intro+method 块——保证每个大纲节都有素材可填；
   **intro/conclusion 块是对卡片背景/结论字段的忠实转述**（只许重组卡片原文措辞，
   **不得新增卡片之外的论断/事实**——防止自由概括脑补）；
   **句级引用锚点（硬约束）**：每个以句号结尾的完整论断句**句尾**标注引用编号 [N]，
   N = 本卡片编号（card.num，制卡阶段分配）；**一句号一句 = 对编号 N 论文的整句引用，
   句内以逗号/分号连接的子句不需要各自标注**；
   MQ（`card_to_json`）**增量流式**：read_sections 边制卡边送（每出一张卡立即入队，
   消费者并发处理），write 节点统一收集；不可用自动降级 ThreadPool 直连。
2. **按节分组（代码确定性归节，v1.2.10：不再要 LLM 选节）**：method 块 →
   卡片 section 所在大纲方法节（不在大纲则择优方法节）；intro 块 → 大纲引言节；
   conclusion 块 → 大纲展望节；block_type 缺失按卡片字段兜底推断。
3. **预算挑选（v1.2.3：超预算=减少引用篇数，不压缩、不截断）**：
   - 方法节按该节**输出预算**（3 节→900/节、4 节→700/节）累计挑选内容块，
     放不下的篇目本轮不引用（未选中自然不进正文与参考表）；
   - 引言/展望把素材块按输入预算（`LEAD_BLOCK_INPUT_BUDGET`）挑选后合并，
     一次 **LLM 概括**（输出 ≤300 字）——**内容与引用编号都交给 LLM**，防错位的关键
     是「编号跟随内容」：A 论文的编号不得挂在 B 论文内容的论断上。
4. **衔接润色**（方法节）/**概括合成**（引言/展望节）：每节一次 LLM——
   - 方法节：合并重复、补衔接词、调语序；**不得新增事实/数字/方法/论文，
     不得改动或新增引用编号 [N]**（素材块自带句级 [N]，润色时原样保留）；
   - 引言/展望（v1.2.13）：概括组织脉络、提炼共性、补衔接词——**每个论断句尾的 [N]
     必须紧跟真正支撑它的素材**（错位红线）；合并多条素材时各编号分别标注在各自论断句尾，
     不得只保留一个编号；不得新增素材之外的论断；不得删除/改写 [N]。
5. **编号校验（确定性，v1.2.11 组装期）**：正文里所有 [N] 必须 = 该块所属卡片的编号；
   写错的编号**强制纠正**为本卡编号（防 LLM 串号）；无编号的块 → 块尾补 [N]（兜底锚点）；
   引用编号随正文句子直达参考文献，不再做块→卡片→编号的二次映射。
6. 超出总预算（3000）/硬上限（4000）：**不压缩不截断，保持全文并提示**，
   评审读到全文并被告知实际字数；字数由第 3 步预算挑选天然控制在预算内。

## 字数分配硬规定（2026-10 v1.2.3，用户决策，覆盖旧比例分配）

- 引言 **~300 字** / 展望 **~300 字**（共 600 字）；
- 中间方法节总 **2400-3000 字**：
  - 方法 3 节 → 每节 **800-1000 字**（取 900）；
  - 方法 4 节 → 每节 **600-750 字**（取 700）；
  - 其他节数 → 剩余字数均分兜底（每节 ≥250）。

## 句式四要素契约（硬约束，任何方法句必须围绕四要素表达）

1. **提出了 XX**（方法/模型名）
2. **通过/用 XX 解决了 XX**（机制 + 针对的难题，必须来自卡片 method 字段）
3. **在 XX 数据集上达到 XX 指标**（数据集 + 数字，**必须来自 experiment 字段/表格，禁止凭印象填**）
4. **（可选）相较 XX 的突破**（对比对象；无卡片证据支撑时不写）

表达示例（措辞可变，核心不变；**以下仅为示例，具体领域必须变通，严禁照抄 PatchTST/ETTh1**）：
- "PatchTST 等提出了 PatchTST，一种将时间序列切分为 patch 的 Transformer 建模方法，
  通过降低注意力复杂度解决长序列预测效率问题，在 ETTh1 等数据集上取得当时最优 MSE/MAE。"（时序示例）
- 纯理论/无实验论文 → 降级为「提出了 XX，一种 XXX，通过 XXX 解决了 XXX」并标注"未提供实验"（**不得编造指标**）。
- 指标形态随领域变化（few-shot 示例：视觉=数据集+mAP/Accuracy、医药=队列+AUC/HR、时序=数据集+MSE/MAE）——一律以卡片 experiment 字段为准，具体领域变通。

### 句式边界（✅ 应该 / ❌ 不应该）
- ✅ **应该**：围绕四要素组织任何方法句；"提出/机制/数据集+指标"必须来自卡片字段；指标数字只从 experiment 字段/表格取；纯理论论文显式标注"未提供实验"。
- ❌ **不应该**：不套用示例领域（PatchTST/ETTh1 只是时序示例，写视觉/医药综述时不得出现）；凭印象填指标；展开卡片之外的实验细节；把"未精读·仅摘要"论文写成有实验数据的方法句；给展望节套用四要素方法句式。

## 写作规则（防幻觉硬契约）

1. 只引用「可引用材料」中明确列出的论文，严禁凭空编造或引用未列出的文献。
2. **材料分两级使用（引用域前移写作阶段，2026-10）**：
   · **精读卡论文**（条目带【精读卡片】、带编号，卡片=原文证据段落含节号）→ 可编号引用、可适当扩展描述方法与实验数据；
   · **未精读论文**（条目带【未精读·仅摘要】、**可编号引用**）→ 统一按「XX等人提出了XXX，通过XXX（方法）解决XXX」**一句话**提及，严禁展开实验数据/数字结论/细节；评审侧标 `weak_evidence` 进低置信清单交用户审核；
   · **展望与未来挑战章节只能基于精读卡论文展开**，未精读论文不得作为展望依据。
3. 严禁编造实验数据、结论、作者；材料里没有的细节不写。
4. 正文引用直接用材料给出的编号（形如 `[12]`），不自行重新编号、不用作者-年份括注——参考文献表由系统按编号自动生成，编号对不上就无法生成。
5. **不写参考文献列表**（也不写占位说明），系统全文结束后自动追加。
6. **篇幅硬约束**：全文建议 **3000 字**（用户明说以用户为准），最大不超过 **4000 字**；
   字数靠预算挑选保证（超预算=少引几篇），**超了不压缩不截断**——保持全文并提示，
   评审读到全文并被告知实际字数，由用户裁量；宁可每节写短也不省略章节，完整性优先于篇幅。
7. 语言专业但可读性强；客观引用，避免主观断言。
8. 评审：**单次评审**（不做多轮重写）。评审报告会列出低置信内容（无锚引用 / 无引用事实句 / 与引用论文相似度低 / NLI 矛盾 / **句式块无证据锚**等）并说明原因，交用户审核；用户可据此要求局部修正（不自动重写整篇）。

## 分节写作执行细节（逐节 LLM 路径，拼接失败时回退用）

- 按大纲分节写作，每节注入该节材料（精读卡论文 + 未精读论文作者/方法行，按 WRITE_SECTION_BUDGET 预算截断；引言/结论节自动退化为全部精读卡论文，不再注入全池摘要）。
- 超预算的节压缩（引言优先压缩），压缩后仍超预算不硬截断（评审会读到全文并被告知实际字数）。
- 参考文献表：系统按正文实际出现的编号拼装真实元数据（GB/T 7714 体例），writer 不参与。
