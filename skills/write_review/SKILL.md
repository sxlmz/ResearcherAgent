# 结构化文献综述

## 用途（何时选）

- 用户要求写一篇**完整、结构化**的文献综述（引言 / 方法分类对比 / 展望 / 参考文献）。
- 「帮我写一篇关于 X 的综述」「做一篇 X 领域的文献综述」。
- **不是**内容询问（"这篇综述讲了什么"是 `answer_from_context`）。

## 图骨架（确定性流程，不由模型决定）

```
parse -> agent (tools) -> write（写作节点：五步流水线拼接，MQ 异步）-> judge（评审节点，单次评审不重写，附评审报告）-> save
```

- 模型在 agent 循环中不再调用工具 → 进入 write 节点；**若一轮检索后全池相关比例均值 < 阈值 → 证据不足拒答**。
- **无用户审核门（v1.2.7 删除 human_review/ask_user）**：大纲定节时已保证每节 ≥5 篇有全文，全部卡片直接用，不再让用户审核范围。

## 五步流水线（2026-10 方案 v1.2 定稿 + v1.2.6 演进调研前置 + v1.2.7 链路精简）

综述生成 = **演进脉络调研 → 按方向定向检索建池 → 演进式大纲 → 定向抽取（全文全量）→ 字段化卡片 → 句式 JSON 块（MQ 异步）→ 拼接+润色+预算 → 单次评审**：

0. **演进脉络调研（v1.2.6 新增第一步）**：调用 `survey_evolution`——Tavily 搜索该主题领域「如何演进」，LLM 梳理 **3-4 个演进方向**（name/era/methods/英文检索词/description）存入 state.evolution_directions。
1. **按方向定向检索建池**：对**每个演进方向**分别用 search_* 定向检索（arXiv / Europe PMC / CORE 三源），每方向找 **10 篇有全文**的论文入 paper_pool（检索源白名单固定三源：arXiv/Europe PMC/CORE；OpenAlex/Crossref/S2 已移除——超时/纯题录/429 不稳定浪费时间）。
2. **演进式大纲**：make_outline 定 **5-6 节**（引言 1 + 技术迭代 3-4 + 展望 1），技术世代由远及近、由浅入深（**方法论最好只列三个，除非实在很多，允许有四节大纲**；世代划分由 LLM 依领域自适应，few-shot 引导，具体领域变通；有 evolution_directions 时方法节尽量与其对应）。**每节必须有 ≥5 篇有全文论文支撑，<5 篇 → 删除该节或并入相邻节**；每节 focus 写清「承接上一代 + 本代方法族 + 待回答问题 + 局限引出下一代」——待回答问题供第 3 步定向抽取定位。
3. **定向抽取（全文全量）**：调用 `read_sections(sections=[方法节1, 方法节2, ...], per_section=10)`——**每个方法节精读重排 top-10**（v1.2.7：read_sections 内嵌全池 Cross-Encoder 重排选候选，无需 check_coverage；共 30-40 篇，按实际节数浮动，上限 40；引言/展望节不单独选文，其素材从 30-40 篇的背景/结论段概括）→ **全篇下载不截断** → 切段带节号+节标题 → 关键词定位四字段（背景/方法/实验/结论，中英变体 + 领域变体词表，few-shot 引导非穷尽）→ 字段内 bge-m3 打分取 top-2 → 关键词全部失效时 LLM 兜底定位（MQ `locate_fallback` 异步，不阻塞下一篇）。**v1.2.11 节级护栏**：重排候选 < 0.35 分直接过滤；每节可精读候选 < 5 篇 → **删除该大纲节或并入相邻方法节（并入则候选合并、卡片 section 用合并后节名，json 大纲自然对应新章节），不再做第二轮补检**（补检浪费时间且返回的多是摘要）；实际精读后仍 < 5 篇的节同样**并入相邻方法节（卡片归属改写）或删除**；已精读足量卡片的节重复调用时直接跳过（幂等）。
4. **字段化卡片**：卡片 = {title, id, section, num, fields:{background,method,experiment,conclusion}, extract_mode}，字段 **100% 原文段落**（带节号），实验字段内表格转 Markdown 保留行列语义，缺失字段标 `"none"` 禁止编造。**v1.2.11 句级锚点**：制卡阶段给每篇论文分配**池内全局编号 [N]**（num 字段），LLM 提取块时在每个论断句末尾直接标注 [N]。**全部卡片直接用（v1.2.7 删除渐进式披露/get_card）**——每节最多 10 篇、卡片全部进入 MQ 内容块生成，无需索引+按需取。
5. **内容块（v1.2.11 流式 + 句级锚点，卡片边制边送 MQ）**：每篇卡片 → 1-3 个 JSON 块 `{block_type: method|intro|conclusion, content, paper_ref(论文标题), evidence(§锚点)}`——MQ `card_to_json` **增量流式**：read_sections 每制出一张卡立即入队（消费者并发处理，与后续下载/补位并行），write 节点统一收集，不可用自动降级 ThreadPool。**大纲归属由代码确定性标注**（method 块 → 卡片 section 所在方法节，intro → 引言节，conclusion → 展望节；LLM 不再选节）→ 按大纲节分组 → 每节**衔接润色一次**（不新增事实/编号）→ 按节预算挑选（`WRITE_SECTION_BUDGET`）→ **句级引用锚点（v1.2.11）**：编号由制卡分配、LLM 直接写进每个论断句（组装期只校验纠正：写错的编号强制改回本卡编号、无编号句补锚点）→ 引用编号随正文句子直达参考文献，**防张冠李戴、防论断无锚** → **超预算时减少引用篇数（不压缩不截断）**。

## 大纲结构契约（确定性校验，make_outline 强制）

**共 5-6 节**：引言 1 节 + 技术迭代 3-4 节（**最好只列三个，除非实在很多，允许有四节大纲**）+ 展望总结 1 节。
- **唯一引言**：含「引言」的节只能 1 个（禁止「1 引言」与「1 引言与问题定义」并存）。
- **唯一展望**：含「展望/结论/总结/未来」的节只能 1 个，且必须有。
- **技术迭代节按「技术世代」由浅入深**（演进式，不是主题罗列）：
  经典/统计时代 → 深度学习初期（RNN/LSTM）→ Transformer 时代 → 后 Transformer 改进/轻量化（近两年）。
  **世代划分由 LLM 依领域自适应**（few-shot：时序/视觉/医药各有世代谱系，仅示例，具体领域变通）；
  **若 state 已有 evolution_directions（survey_evolution 产物），方法节尽量与其对应**。
  每节 focus 写清「承接上一代解决了什么 + 本代方法族与待回答问题（供抽取定向）+ 局限引出下一代」。
- **每节必须有 ≥5 篇有全文论文支撑**（<5 篇 → 删除该节或并入相邻节）；大纲是「有全文素材的聚类结果」，严禁硬列无全文空节。
- 近两年（后 Transformer）节是**热门研究方向证据源**：检索时保证该节有近 2-3 年文献，其精读卡片可为「新兴方向探查」等下游功能复用。

## 关键硬约束（写作时不可违反）

- 只引用可引用材料中明确列出的论文，严禁凭空编造；正文引用直接用材料给出的编号（形如 `[12]`），不自行重新编号。
- **句式四要素硬契约**（方法句必须围绕四要素表达，漏一项不合格）：①提出了 XX ②通过/用 XX 解决了 XX（机制+难题，必须来自 method 字段）③在 XX 数据集上达到 XX 指标（数字必须来自 experiment 字段/表格，禁止凭印象）④（可选）相较 XX 的突破（无卡片证据不写）。纯理论/无实验论文降级为「提出了 XX…」并标注"未提供实验"。
- **材料按证据约束分两级（引用域前移写作阶段）**：
  · **精读卡论文**（条目带【精读卡片】、卡片=原文证据段落）：可编号引用，可适当扩展描述方法与实验数据；
  · **未精读论文**（条目带【未精读·仅摘要】，**可编号引用**）：统一按「XX等人提出了XXX，通过XXX（方法）解决XXX」一句话提及，**严禁展开实验数据/数字结论**；评审侧标记为**摘要级弱证据（weak_evidence）**进低置信清单交用户审核；
  · **展望与未来挑战章节只能基于精读卡论文展开**。
- **不写参考文献列表**（系统全文结束后自动追加）。
- **篇幅硬约束**：全文建议 **3000 字**（用户明说以用户为准），**最大不超过 4000 字**（超 4000 强制整篇压缩）；完整性优先于篇幅。
- 评审：**单次评审**（不做多轮重写），综述先交付，附评审报告（含低置信内容清单与原因），低置信点交用户审核。评审含**确定性证据锚校验**：句式块无证据锚的引用 → low_conf。

## 检索源选择策略（v1.2.8 定稿：白名单固定 arXiv + Europe PMC + CORE）

| 源 | 特点 |
|---|---|
| search_europepmc | 开放获取全文通路（PMCID → JATS 全文 XML 直取） |
| search_arxiv | 偏预印本/最新工作；100% 全文可达（ar5iv） |
| search_core | CORE v3（OA 全文文本，需 CORE_API_KEY；配 key 后稳定） |

某源返回 0 条时换另一个源，不要反复重试同一源（源熔断时工具会直接告诉换哪个）。

**已移除（不再使用）**：`search_openalex`（本轮 E2E 多次 ReadTimeout 20s，网络不稳定拖慢检索）；
`search_crossref`（多为题录、无全文线索，综述要全文，纯题录浪费时间）；
Semantic Scholar（整体移除，v1.2.8 用户决策：无 key 时 1 req/s 节流 + 429 频繁，不稳定；
检索与全文通路均不再使用该源；novelty_check 等场景另有独立检索链路，不受影响）。

## 与其他 skill 的关系

- 配 `judge_review`（学术质量评审）是标准组合。
- 可配 `search_papers`（文献来源）、`index_file`（文件素材）、`code_exec`/`innovate`（综述→创新点验证的延展）。

## 坑位与经验

- 只搜主题词容易漏侧面——先 survey_evolution 拆演进方向，再按每个方向分别定向检索（检索词带领域限定词）。
- 陈旧/不相关池子会触发"证据不足拒答"门：宁可多检索一轮也不要硬写。
- 大纲驱动优于自由问答：先定 5-6 节结构再逐节补料。
- 拼接路径失败（无 JSON 块/缺节）会自动回退逐节写作，不阻塞交付。
- MQ 不可用自动降级 ThreadPool 直连（不阻塞）。
